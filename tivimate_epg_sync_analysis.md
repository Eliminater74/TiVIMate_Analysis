# TiViMate Reference Analysis — EPG Synchronization Workers

This document provides a highly detailed architectural analysis of **TiViMate’s** EPG synchronization workers, dissecting their execution flow, background threading configurations, and persistence mechanisms.

---

## 1. USER-FLOW LEVEL BEHAVIOR
* **Automatic Background Updates**: The user configures EPG updates to trigger at specific intervals (e.g., every 2, 4, 12, or 24 hours) via the UI Settings screen.
* **System-Managed Recovery**: EPG updates run silently in the background when the device is idle, awake, or rebooted. The user sees an "EPG updated" toast notification or status label when they next open the app, with zero scrolling stutters during active background writes.
* **Force-Sync Control**: The user can navigate to Settings -> EPG and click "Update EPG" manually. This triggers a visual progress loader that updates EPG rows incrementally without disrupting active player video streams.

---

## 2. ARCHITECTURAL PATTERNS under the hood
* **Room-Backed WorkManager Wrapper**: TiViMate leverages Android’s **WorkManager** framework backed by a Room database (`WorkDatabase`) to schedule and orchestrate background operations.
* **Transaction-Guarded State Machine**: All worker states (ENQUEUED, RUNNING, SUCCEEDED, FAILED) are transactionally written to SQLite. Work execution is delayed if system schedules conflict, using B-tree indices to seeking tasks efficiently.
* **Write-Ahead Logging Isolation**: The underlying Room/SQLite database runs in WAL journal mode with synchronous operations set to normal. Background EPG parsing threads write EPG programs into SQLite in long batch transactions. Because of WAL mode, these massive write transactions do not block the active UI player thread from executing read EPG queries.

---

## 3. CLUE SOURCE (CLASSES & FILES)
* **`sources/p262/C3419.java`** (The core Worker wrapper task dispatcher):
  * Imports `androidx.work.WorkerParameters`, `androidx.work.impl.WorkDatabase`, and `androidx.work.impl.WorkerStoppedException`.
  * `m7311(C3419 worker, ...)`: Orbits the coroutine lifecycle of worker execution. Intercepts worker status and checks if the active task is `ENQUEUED` before starting execution.
  * Dynamically schedules task execution delays using `System.currentTimeMillis()` mapped against the EPG source schedule limit (`c3232.m7061()`).
  * Utilizes `androidx.work.OverwritingInputMerger` to merge incoming arguments and configures trace events using `Trace.class.getMethod("asyncTraceBegin", ...)` to benchmark synchronization performance.
  * Handles transaction commits safely within `WorkDatabase` blocks.

---

## 4. CONCEPTUAL REPLICATIONS FOR PUREFUSIONIPTV
* **WorkManager Orchestration**: Schedule all recurring playlist and EPG updates using WorkManager’s `PeriodicWorkRequest` or `OneTimeWorkRequest` rather than raw background threads or unmanaged alarm services that the OS can easily kill.
* **WAL Mode Enforcement**: Configure your Room database builder with `setJournalMode(RoomDatabase.JournalMode.WRITE_AHEAD_LOGGING)` and set `PRAGMA busy_timeout = 3000` to prevent database locks when the background worker is writing millions of EPG records.
* **Delay/Surf Safety Constraints**: Prevent redundant EPG updates on startup by checking the `last_update_time` and validating if the configured update interval has actually elapsed before enqueuing a sync job.

---

## 5. DIRECT COPYING WARNINGS (DO NOT COPY)
* **Obfuscated Key Classes**: Avoid copying class names or structures from `p262.C3419` or `p240.C3231`. These represent compiler-obfuscated entities generated by R8/Proguard when packaging WorkManager and Room entities.
* **Low-Level Transaction Wrappers**: Do not write custom transaction execution code like `workDatabase.m3758(new C0185(...))`. Modern Kotlin Coroutines support `database.withTransaction {}` out of the box, which is much cleaner and type-safe.

---

## 6. IMPLEMENTATION RISKS
* **Main Thread Disk IO Block**: Running EPG parsing directly on the Worker's default thread can lock out other database operations if you do not shift the context explicitly to `Dispatchers.IO`.
* **Battery Saver Restraints**: Modern Android versions (especially on Android TV/Google TV devices) aggressively restrict background services. If background workers do not specify `NetworkType.CONNECTED` and `RequiresCharging` constraints, the OS may defer EPG updates indefinitely.
